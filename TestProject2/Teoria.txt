[Fact] //se usa para hacer test a un solo escenario 
[Theory]: Marca el método de prueba como parametrizado y requiere que se proporcione una fuente de datos.
[InlineData]: Atributo más simple para pasar valores primitivos directamente en la línea de código.
[MemberData]: Permite definir los datos de prueba en una propiedad, campo o método estático de la clase de prueba.
[ClassData]: Utiliza una clase externa que implementa IEnumerable<object[]> para proveer los datos, útil cuando la lógica de generación de datos es compleja.
TheoryData: en versiones modernas de xUnit puedes utilizar TheoryData<T1, T2> para definir los tipos de los argumentos explícitamente.
[Trait]: es un atributo que permite clasificar y categorizar tus pruebas mediante pares de clave y valor. 
Esto te permite organizarlas, filtrarlas y ejecutar grupos específicos de pruebas sin tener que ejecutarlas todas.

Custom Data Attributes: son atributos personalizados que puedes crear para proporcionar datos a las pruebas parametrizadas de xUnit. (otra manera de proporcionar datos y usarlos en las pruebas)

ssert.Equal() y Assert.StrictEqual() se utilizan para comprobar que dos valores son iguales, pero la diferencia está en cómo se compara la igualdad de las colecciones.

Assert.Same() y Assert.NotSame() comparan identidad de objetos, es decir, si dos variables apuntan exactamente a la misma instancia en memoria.
Equal pregunta «¿son iguales?». Same pregunta «¿es el mismo objeto?». NotSame pregunta «¿son objetos distintos?».
Assert.NotSame(): comprobar que se crea un objeto nuevo

[MemberData]: //es un atributo que permite proporcionar múltiples conjuntos de datos a una prueba parametrizada
//obteniéndolos desde un método, una propiedad o un campo estático de una clase.
//en lugar de escribir los valores directamente en el atributo, indicas dónde puede encontrarlos xUnit.
public class CalculadoraTests
{
    public static IEnumerable<object[]> CasosDeSuma =>
        new List<object[]>
        {
            new object[] { 2, 3, 5 },
            new object[] { 10, 5, 15 },
            new object[] { -1, 1, 0 }
        };

    [Theory]
    [MemberData(nameof(CasosDeSuma))]
    public void Sumar_DosNumeros_RetornaResultadoEsperado(
        int a,
        int b,
        int esperado)
    {
        var calculadora = new Calculadora();

        var resultado = calculadora.Sumar(a, b);

        Assert.Equal(esperado, resultado);
    }
}

yield return: C# genera automáticamente un iterador que va proporcionando los elementos cuando alguien los solicita.
Permite devolver elementos uno por uno de una colección, sin tener que construir y devolver toda la colección manualmente.

SON EQUIVALENTES
public static IEnumerable<object[]> GetData()
{
    yield return new object[] { GetName(), 5 };
    yield return new object[] { "One two three", 3 };
    yield return new object[] { "One two three four", 4 };
}

public static IEnumerable<object[]> GetData()
{
    return new List<object[]>
    {
        new object[] { GetName(), 5 },
        new object[] { "One two three", 3 },
        new object[] { "One two three four", 4 }
    };
}


La idea central es que ClassData no ejecuta las pruebas ni contiene la lógica de negocio. Su responsabilidad es proporcionar los argumentos que xUnit utilizará para ejecutar una teoría.
